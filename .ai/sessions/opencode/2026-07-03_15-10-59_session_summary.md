## Architecture Decisions

1. **Identity app structure** — Added `services.py`, `selectors.py`, `validators.py` to `apps.identity` following the service-layer pattern. No signals (no justified need). Admin enhanced with fieldsets, readonly timestamps, `display_code` in list_display.

2. **Person.code is the global ERP identifier** — `StudentProfile.code` / `StaffProfile.code` are operational codes. Templates use `person.display_code`, not legacy `h_code`.

3. **Test-DB role switching** — `bisk/settings.py` switches to `TEST_DB_USER`/`TEST_DB_PASSWORD` when `"test" in sys.argv`, allowing the `bisk_test` CREATEDB-enabled role for test runs without affecting normal DB config.

4. **Academics app — year-scoped Section** — `Section` belongs to both `AcademicYear` and `Grade` (not year-agnostic). Identity key is `(academic_year, grade, code)`. Homeroom adviser on Section is inherently year-scoped. Capacity is year-specific.

5. **Section placement history** — `StudentEnrollmentSectionPlacement` model tracks section transfers as an append-only history. Only one `is_current=True` per enrollment (DB partial unique constraint). Transfers close the previous placement and open a new one.

6. **Capacity uses current placements** — `validate_section_capacity` counts `StudentEnrollmentSectionPlacement` rows with `is_current=True`, not stale `StudentEnrollment.section` FKs. Withdrawn/graduated/repeated students don't consume capacity.

7. **Enrollment lifecycle** — Status enum state machine (future/active/transferred/withdrawn/graduated/repeated/archived). `withdraw()`/`graduate()`/`repeat_year()` close the current placement. History is append-only.

8. **AcademicYear single-active** — DB-level partial `UniqueConstraint` ensures only one `is_active=True` row.

9. **Lunch domain — separate `apps.meals`** — Lunch subscription/eligibility/attendance/supervisor-action/exception entities designed. `LunchEligibility` is the canonical daily decision (recalculable until a `LunchServiceEvent` references it, then frozen). Lunch must not own wallet math.

10. **Finance domain — immutable ledger** — `Wallet`/`WalletTransaction`/`Charge`/`Payment`/`Refund`/`Adjustment`/`PricingRule` designed. Balance is a cached projection; ledger is the source of truth. Discounts are NOT owned by finance — they belong to a future `apps.discounts` domain; finance consumes results via service boundary.

11. **Attendance migration drift** — Discovered that `0001_initial` and `0001_squashed_0021...` are both recorded as applied; squash was fake-applied; `confirmed`/`lunch_*` fields never applied to DB. `models.py` was edited to match DB state. Recommendation: freeze attendance migrations, build new apps separately, defer squash.

12. **New domain app name is `apps.meals`** (not `apps.meal` or `apps.lunch`) — supports multiple meal periods (breakfast, lunch, etc.).

13. **OpenCode session log policy** — Raw logs to `.tmp/opencode/` (gitignored); committed records under `.ai/sessions/opencode/` must be concise Markdown summaries; avoid >5 MB, never >50 MB.

## Important Risks Discovered

1. **Attendance migration drift (CRITICAL)** — Both `0001_initial` and `0001_squashed_0021...` recorded as applied; squash fake-applied; `confirmed`/`lunch_*` fields never applied to DB. `resources.py` references non-existent fields. `LunchSubscription`→`MealSubscription` was destructive. Full details in `legacy_lunch_wallet_attendance_investigation.md`.

2. **Wallet balance directly mutated in views** — `apps/attendance/views.py` mutates `wallet.balance_iqd` and creates `WalletTransaction` rows inline (lines ~1094, 1144, 1229). No service boundary. Highest-risk code to migrate.

3. **`views_.py` is a stale duplicate** of `views.py` — maintenance hazard.

4. **Discount engine entirely missing** — Models/admin exist but `discount_iqd` is always 0; no resolution logic.

5. **CI may diverge from production** — Fresh `migrate` produces squash-honest schema (with `confirmed`/`lunch_*`) which differs from production DB.
